# Community operations

User-approved extension on 2026-11-13. Surface mode: Operate. Extends the existing AI Copilot with a Community view, reusing the established graphite/cold-white/citron system and existing wallet ownership checks. The working loop is **invite → review → publish → register → record attendance → recap**. No visual identity replacement or design-system change is introduced.

## Implemented behavior

- Community links support an HTTPS website, X profile, Telegram link and a Discord invitation. The creator explicitly chooses public or private visibility. Public visibility is also bounded by the existing verified project's publication state. Third-party destinations are links, not claims of membership, endorsement or ownership.
- Events start as private drafts. Invitations have a title, description, local-time editor, start/end, optional join URL and optional capacity. Each event permits at most 500 registrations. A creator may store up to 100 events. Publishing requires a verified published project page, a future start and explicit confirmation. Saving edits preserves the previous public invitation until another confirmed publication. Capacity cannot be republished below the current registration count.
- Visitors sign in with a wallet message before registering. No token purchase, payment, transaction or distribution of rewards is involved. Duplicate registration is idempotent; a SQLite transaction enforces capacity. Attendee addresses are owner-only. Public responses show counts and only the signed-in visitor's own registration state. Registration closes when the published start is reached, or the event is cancelled/completed/hidden. A visitor may withdraw later, while the project page is available.
- Attendance is explicitly recorded by the creator after the published event start; it is not automatic attendance verification. Completion requires a factual creator recap. The recap stays private unless the creator explicitly shares it. Cancellation keeps the public invitation and a required cancellation note. Community links, event plans, registration counts and creator-supplied outcomes are included in Copilot context without attendee wallet lists.
- X posts form a private queue. Existing saved social drafts can be reused, or the creator can write a post manually. Text is capped at 280 Unicode code points; X applies its own weighted limits. Edits revoke approval. API approval binds the exact revision and connected-account generation. Publication requires separate confirmation; connecting an account or approving a post never sends a post. There is no scheduled social publication.
- Confirmed API posts retain the actual post ID/URL. A manual results request reads public likes/replies/reposts/quotes from X and timestamps the observation. Missing data stays missing. Verified receipts and these observed results feed the next Copilot review; the system does not infer attribution, sentiment, full audience size or membership. Opening an X intent only prepares a draft in X; it does not create a verified publication receipt.

## Account boundary and configuration

Credentials stay in the existing ignored server environment. This change adds blank optional entries to `.env.example`; it does not modify the real `.env` or existing provider credentials.

Configure an X **confidential OAuth 2.0 client**, using the official [PKCE documentation](https://docs.x.com/fundamentals/authentication/oauth-2-0/authorization-code), [post endpoint](https://docs.x.com/x-api/posts/create-post) and [current-account endpoint](https://docs.x.com/x-api/users/get-my-user). Required server configuration:

- `X_CLIENT_ID` and `X_CLIENT_SECRET` for the app.
- `SOCIAL_ENCRYPTION_KEY`: 32 random bytes encoded as Base64. Keep it stable and back it up securely. Replacing it requires affected accounts to reconnect.
- Register exactly `APP_ORIGIN/api/social/x/callback` in X. The local default is `http://127.0.0.1:4318/api/social/x/callback`. X account permissions and service access must allow the requested endpoints; service-side limits are not bypassed.

Scopes: `tweet.read tweet.write users.read offline.access`. PKCE uses S256, random one-use state and a ten-minute HttpOnly SameSite=Lax browser-binding cookie. Callback credentials remain in server memory until a same-origin POST by the original verified wallet completes connection. Account tokens are encrypted with AES-256-GCM and wallet/project associated data before persistence. API responses never contain token ciphertext, access tokens, refresh tokens or client secrets. Refresh happens only for an explicitly requested post or results read. Disconnect deletes the local token connection and pending flows; users can also revoke the app within X.

Publishing has a persistent sending state and an in-process lock. Network/response uncertainty becomes `uncertain` and is not automatically retried. A process crash can leave a `sending` record, also ineligible for another send. Users must check X; do not fabricate a receipt or silently retry. Definite rejections may be edited/reapproved. Reconnecting even the same account invalidates earlier account approvals.

- 54 Node tests pass, including seven community/X groups. Checks cover real SQLite transactions/persistence, public snapshot preservation, stale revisions, capacity contention, privacy, RSVP/attendance/cancellation, PKCE challenge and browser binding, delayed wallet finalization, token encryption, invalidated account approval, token refresh, duplicate-send prevention, uncertain/definite failures, receipts, observed metrics and authenticated HTTP owner/CSRF boundaries. TypeScript and production build pass. The existing Ganache native transport warning falls back to its JS implementation.
- Browser verification uses actual components and storage modules against an isolated loopback fixture, clearly labelled with illustrative project, account and results. No real external request, X post, Discord message, provider generation or wallet transaction is made. It covers failed-save preservation/retry, draft/public states, registration, separate X approval/publication, receipts/results and Discord link validation. Two visual rounds include 1440px desktop, 768px tablet, 390px phone and 320px narrow layouts. The first pass's long default form was replaced with a summary and explicit Edit invitation action; editing uses 16px text on small containers.
- Independent finish review identified three bounded fixes: authoritative X delivery recovery, retained edits during revision conflicts/read failures, and mobile editor focus. The final reviewer verdict scores F1–F3 resolved; it is not a whole-product audit. Browser recaptures verify sending is disabled when state cannot be read, uncertain posts have no resend control, all affected forms freeze during backup recovery, copied/acknowledged changes permit explicit reload, and discarding the first event focuses its empty-state heading. Clipboard API availability varied in the in-app browser; manual text selection/copy plus explicit acknowledgement was verified as the fallback.
- The updated application on port 4318 passed a separate authenticated acceptance with an unfunded deterministic local test wallet: private community links, private event, offline X draft, denial of publication before project publication, denial of account connection while unconfigured, anonymous access denial and hidden private project page. Zero social posts, paid AI requests or financial transactions were sent. Only the exact temporary wallet/project records were removed; existing projects and watchlist were checked afterward. Evidence: `running-product.json`.
