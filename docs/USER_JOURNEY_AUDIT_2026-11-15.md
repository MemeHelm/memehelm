## 结论与范围

功能面已经覆盖发行后的运营，不只是发射台，但仍属于需要修复闭环和异常恢复的本地版本。不能据此宣称功能全部完善、资金流程经过正式验收或没有安全漏洞。

本轮为只读审查：检查当前前后端、合约及测试；在真实浏览器检查未登录用户的桌面、发币入口、AI 入口和搜索键盘行为；使用模拟钱包/RPC 检查故障路径。未改业务代码，未使用真实签名或广播交易，未调用付费 AI，未发社交消息，未读取环境密钥。

`pnpm test` 完整运行结果：111 项通过、0 失败，约 70 秒。测试包含本地模拟链，不代表主网用户已完成验收。现有测试没有覆盖本报告中多处跨组件交接和广播后中断场景。近期 UI 构建已通过；本轮未修改 UI，因此没有重新构建。

## 必须先修复的资金流程问题

### F01 · P1 · 广播成功后没有持久化交易恢复

- **触发：** 钱包已返回交易哈希，随后 RPC 断线、切链或关闭页面。
- **影响：** 链上可能成功，前端却只报普通错误或丢失当前操作。用户重新发币/交易可能再次支付费用。并非已经证明发生重复扣款，而是现有流程缺少判断和恢复依据。
- **依据：** `src/wallet.ts:34` 取得哈希后才轮询收据，查询异常直接向上抛出；`src/main.tsx:67` 仅在收据和事件取得后保存发行恢复记录。交易、激活金库和收益操作也复用该钱包方法。
- **验证：** 模拟 provider 返回一次广播哈希，随后的收据请求抛错；错误没有保留可恢复哈希。未广播真实交易。
- **修复：** 广播时保存钱包、链、哈希、业务上下文；显示“已提交，待确认”，支持刷新后继续查询，避免把查询失败当作交易失败。实际失败、取消、替换和仍待确认应分别处理。

### F02 · P1 · 持币人分红和社区托管发行后丢失金库关联

- **触发：** 激活 holders/social 金库并成功发行。
- **影响：** 金库已创建且作为收费目的地，但工作空间保存为无关联金库，收益页缺少分红/托管控制。资金并未因此证明丢失，但用户无法正常继续。
- **依据：** `src/main.tsx:67` 只在 `splitEnabled` 时提交 `vaultAddress`；`server/index.mjs:164` 和 `server/pons.mjs:122` 依赖保存的关联。
- **修复：** 四种收益模式统一保存和核验正确关联，提供已有项目的只读核对及补关联路径。不能要求用户重复发币或重复部署金库。

### F03 · P2 · 当前手动 X 模式无法走完社区托管释放

- **触发：** 无 X 开发者应用时，用户选择社区托管，提案经过两天窗口后申请释放。
- **影响：** 发币页允许启用，但释放接口要求保存的 OAuth 账号，手动发帖不能满足，因此产品中断。控制者仍可直接调用链上合约；这不是证明资金永久锁死。
- **依据：** `src/LaunchWizard.tsx:52` 提供激活；`server/index.mjs:252` 执行前检查 `social.get(project).account`；`server/social-manual.mjs:30` 不产生该账号。
- **修复：** 在付 gas 前检查模式前置条件，或设计与手动身份模式一致的可行释放流程；检查账号存在不能直接宣称连接仍有效。

### F04 · P2 · 持币人分红失败后没有可行恢复流程

- **触发：** 快照纳入一个拒收 ETH 的持币合约。
- **影响：** 整轮原子回滚，每次重试仍包含同一地址，其他收款人也无法领到。原子回滚本身保护资金一致性，缺失的是失败后的产品路径。
- **依据：** `contracts/src/HoldersVault.sol:66`；`test/contracts.test.mjs:53` 明确验证拒收导致整轮回滚；`server/pons.mjs:155` 继续按生成名单模拟。
- **修复：** 设计可解释、可审阅的失败地址处置或领取机制，不静默更改分红资格。修改合约策略需要独立评估，不能当作单纯 UI 修复。

### F05 · P2 · 分红审核页不能核对完整收款名单

- **触发：** 分红超过八个收款地址。
- **影响：** 页面只显示八个地址和其余数量，却要求用户审核签名。
- **依据：** `src/TreasuryWorkspace.tsx:39` 使用 `slice(0,8)`，无完整展开/导出。持仓来源只读一页，具体限制由 `server/market.mjs:49` 和分配规则决定。
- **修复：** 展示完整地址和金额，支持导出，并清楚显示采样范围、纳入/排除数量与最低金额。已有“快照内按比例”提示不等于全名单可核对。

## 信息正确性与异常恢复

### F06 · P2 · X-Ray 毕业目标的单位错误

- **影响：** 原始整数直接标为 ETH；测试样例的 0.42 ETH 会显示为 420,000,000,000,000,000 ETH。这是显示缺陷，未据此证明实际转账金额错误。
- **依据：** `server/market.mjs:91` 返回原始 `graduationThreshold`，`src/MarketWorkspace.tsx:56` 直接数值格式化并加 ETH。
- **修复：** 按实际报价资产精度格式化并展示其币种，增加六位和十八位资产的 UI 断言。

### F07 · P2 · 查询失败被写成否定事实

- **影响：** RPC 故障会把实际 pons 代币标为“不是 pons 发行”；收款地址类型查询失败被显示成“合约”。错误事实也可能进入 AI 上下文。
- **依据：** `server/market.mjs:73,89`，`src/MarketWorkspace.tsx:55,60`。
- **验证：** 内存模拟注册读取失败，确实得到 `registered:false` 和未注册标记。
- **修复：** 区分已确认、已否定、无法查询三态；未知不得作为风险或来源结论。

### F08 · P2 · 导入成功不代表地址确实是代币

- **触发：** 填入格式正确的普通钱包地址或其他链地址，不填金库。
- **影响：** 项目显示已导入，行情与快照之后失败。
- **依据：** `server/index.mjs:160–173` 此分支仅校验地址格式，未校验链上合约及代币接口。
- **修复：** 导入前核验 Robinhood 上的代码和代币元数据；查询失败提供重试，而不是保存伪成功。公开发布另有验证，本项不是已发现的所有权绕过。

### F09 · P2 · 社区托管公开页和历史提案不完整

- **影响：** social 金库被公开页当作两钱包固定分账，显示 Project100%/Reserve0% 等不适用字段；最近十条以外的旧提案没有分页或按编号继续操作入口。提案读取失败会被伪装成空列表。
- **依据：** `src/PublicProject.tsx:22`；`server/pons.mjs:191`；`src/TreasuryWorkspace.tsx:13`。
- **修复：** 按金库类型显示真实规则；提供提案分页/编号查询和错误重试，不把读取失败显示为没有提案。

### F10 · P2 · 恢复联网后的状态仍误导用户

- **影响：** Signals 后续刷新成功仍保留之前的错误；社区发现列表加载失败却显示普通空状态。
- **依据：** `src/SignalsWorkspace.tsx:13–14`，`src/MarketWorkspace.tsx:80`。
- **修复：** 成功时清除已解决错误；区分从未加载、加载失败、确实为空和旧数据，并提供对应重试。

## 内容与运营用户的流失点

### F11 · P2 · 关闭 AI 窗口会丢失未保存表单

- **触发：** 编辑项目记忆、日历或社区内容后点击关闭 AI Copilot 窗口。
- **影响：** 组件卸载，未保存内容消失，没有提示。最小化会保留。
- **依据：** `src/Desktop.tsx:124–134` 删除窗口；`src/CopilotWorkspace.tsx:20–23` 的编辑阻塞仅限制内部导航；`OperationsWorkspace.tsx:24`、`ContentCalendar.tsx:14`、`CommunityWorkspace.tsx:15` 使用本地编辑状态。
- **修复：** 将未保存状态传到窗口层，提供继续编辑/保存后关闭/放弃，或按钱包与项目安全暂存草稿。刷新和会话结束也需要明确策略。

### F12 · P2 · AI 回复失败时用户问题消失

- **依据：** `src/ProjectChat.tsx:68,74` 先清空输入框，失败后删除乐观消息，不恢复问题。
- **修复：** 保留失败条目并提供重试或恢复输入；不能让用户重新写长问题。

### F13 · P2 · AI 文案不能顺畅进入社区发布草稿

- **影响：** 模型同时返回推文和事实依据，社区却把整段当作推文导入；可能超过280字符无法保存，也可能把依据说明带入发布正文。
- **依据：** `server/copilot.mjs:36`，`server/index.mjs:229`，`src/CommunityWorkspace.tsx:103`。
- **修复：** 分离正文与依据，提供明确的“加入内容计划/帖子队列”交接，保留审核。

### F14 · P3 · 聊天静默淘汰历史且无导出

- **依据：** `server/index.mjs:206,208` 保留最多20个会话及每会话40条消息，前端没有相应保留范围说明和归档导出。
- **影响：** 长期用户可能误以为完整对话会永久保留。
- **修复：** 告知上限，提供归档/导出或更明确的保留策略。

### F15 · P2 · 搜索弹窗的键盘焦点能逃到背景

- **浏览器复现：** 打开搜索，在初始输入框按 Shift+Tab，焦点到达背景的“Minimize Mate character”，而搜索仍打开。
- **依据：** `src/SearchPalette.tsx` 声明模态对话框，但没有焦点约束、背景 inert 或关闭后焦点恢复。
- **影响：** 键盘及辅助技术用户会在不可见/遮挡区域操作；输入框以外的 Escape 也缺少一致处理。
- **修复：** 完整实现模态焦点、Escape 和触发按钮焦点恢复，不只加 aria-modal。

## 待专项验证的风险

前端聊天/写作约65秒超时，服务端在读取事实后才开始模型自身约60秒的超时；慢查询和慢模型叠加可能出现前端失败、服务端随后保存并消耗额度。聊天/写作缺少请求幂等和恢复查询，重试可能重复生成。此项为源码发现的可能路径，未用真实付费调用复现，不能表述为已经发生重复计费。应使用模拟延时测试补证并设计请求状态恢复。

## 功能边界，不应混作漏洞

- 没有跨链发行和自动做市是已确认的产品范围，不需要补回来。
- 手动 X 发帖是已接受的模式；不能声称其验证了真实账号、发布正文或互动数据。Discord/Telegram 目前不是机器人运营。
- 图片上传/IPFS 自动存储尚未接入。选择本地图片仅作预览，用户仍需托管链接。
- 当前监控依赖本地后端在线，提醒在应用内；没有外网部署、离线推送或无人值守服务保证。
- 发现和行情是有界索引；没有完整历史、任意交易对、独立新闻/社交数据源或美元估值服务。
- 独立安全审计、生产备份/恢复、多实例会话、服务运维和真实主网用户验收尚未完成。当前内存会话在后端重启后要求重新登录。
- 未在本轮发现所审私有路由跨钱包读取、绕过签名直接执行资金操作的明确路径；这不是完整渗透测试或无漏洞保证。
- 源码/公共素材/文档的凭证格式扫描未匹配到所检查的长 `sk-` 形式。扫描范围有限，且本轮未读取环境文件，不能据此声明所有历史提交均无秘密。
