# 阶段 B 首个切片：可恢复发行事件索引

用户日期：2026-11-17。本文所有证据时间使用 UTC；实测发生在 2026-11-16 UTC。基线为 `f67d59e` 加当前工作区的已实现改动，不表示已提交、推送、部署或完成整个增强计划。

## 已实现范围

- 新增独立 SQLite 事件、区间和状态表，不把不断增长的历史塞进 JSON 文档集合。身份绑定 Robinhood 4663、官方 factory 地址、预期字节码哈希和 schema 版本。
- 第一次观察从 `head - 19999` 开始；高度不足时从 0 开始。没有猜测 factory 部署高度，也不声称覆盖此起点之前的发行。
- 每次读取固定 target；按连续区间提交。事件、区间终点哈希和下一块游标在同一事务中提交，失败不越过缺口。重启后从保存的缺口继续。
- 校验 chain、事件名/emitter、六个事件参数、区块号/哈希、交易哈希、日志位置和 canonical header 时间；拒绝冲突重复、同块位置冲突和同交易跨块矛盾。
- 每次续读核对检查点。确认分叉后先原子隔离待核验记录，再寻找保留的共同检查点；浅层回滚重读，超出有界回溯时清除旧观察范围并从新的近期起点重建。发现失效记录的同一次响应即撤回卡片，不把已知孤块当作离线旧数据继续展示。
- 记录并返回实际覆盖、缺口、最后读取/链核对 UTC 时间、预览限制、事件总数、`allTime:false` 和 `finality:observed`。预览最多 200 个事件，Discover 最多展示其中最新 30 个不同 token，历史原始事件仍留在数据库。
- 普通 RPC 失败保留上次仍未被证明失效的记录并标示 saved；名称/符号读取失败仍保留发行回执和区块时间。缓存元数据按交易、日志位置、区块哈希隔离，失败或非法新值不会刷新旧元数据时间。
- Discover 展示实际范围，支持展开查看、手动刷新与 60 秒读取；社区页面仍独立加载。手机卡片根据主内容可用宽度切换单列，范围详情采用标签与值上下排列。

主要代码：`server/launch-index.mjs`、`server/launch-index-repository.mjs`、`server/workspace.mjs`、`server/market.mjs`、`server/index.mjs`、`src/LaunchHistoryCoverage.tsx`、`src/MarketWorkspace.tsx`、`src/launch-history.css`。

## 执行预算与恢复

- 索引单轮默认最多 4 个区间，每段最多 5000 块，最多 48 次 RPC 方法调用、总计 8 秒，单请求最多 2.5 秒。高密度日志会缩短提交终点，不能采样后跳过事件。
- 整个 feed 另有协议核验最多 5 秒，以及最多 30 个 token × 3 项元数据读取，每项最多 2 秒；整个 feed 截止 16 秒。**48 次是索引预算，不是完整 Discover 请求的总预算。**
- 手工刷新可跳过普通 60 秒缓存，但保留最短 5 秒间隔；同实例并发请求合并，超时晚到结果不继续提交。这里只承诺单 Node 实例，不承诺多 worker 的分布式协调。
- 这是按 Discover 请求推进的索引。关闭页面后不会无界扫描或自动购买 RPC/AI 服务；大缺口分多轮恢复。深分叉重建可能缩小历史，API 与页面如实显示新起点。
